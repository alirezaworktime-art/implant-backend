# m47a — جلسه‌ی پروتز: «ارسال کار برای لابراتوار» (۱۴۰۵/۰۸/۲۷ — 2026-11-17)

ورودی: باندل m46c. صفحه + سرور (دو لنگر در `labNew` + بلوک انتهایی).

## خواسته‌ی مالک
پزشک اول کار همان جلسه را با جدول دندانی (پایه / پونتیک) ثبت کند؛ آخر آن یک دکمه‌ی «ارسال کار برای لابراتوار» باشد که دستورکار لابراتوار را باز کند، هیچ فیلدش اجباری نباشد و فایل‌ها همان‌جا بارگذاری شود.

## قبل از این وصله
صفحه‌ی «جلسه‌ی پروتز» (کارتابل پزشک پروتز / جراح، دکمه‌ی «جلسه‌ی پروتز» روی کارت بیمار) نوع کار (۱۳ نوع) + جدول دندانی پایه/پونتیک + توضیح را داشت، ولی برگه‌ی دستورکار همیشه زیر آن باز بود و برای ارسال، «ایمپلنت»، «Type»، «material»، «ساخت برای»، دندان پایه و تاریخ تحویل اجباری بود.

## بعد
- صفحه: اول «کار این جلسه» (نوع، جدول دندانی، مجدد، چسب، مبلغ، توضیح). زیر آن دکمه‌ی **«ارسال کار برای لابراتوار»**؛ پایین صفحه فقط «ثبت جلسه».
- با زدن دکمه، دستورکار باز می‌شود (سربرگ «دستورکار لابراتوار» + «بستن دستورکار»)؛ ستاره‌های اجباری برداشته شده؛ پایه/پونتیک برگه از جدول همین جلسه پر می‌شود (و با تغییر جدول به‌روز می‌شود تا وقتی پزشک خودِ برگه را دست نزده)؛ جعبه‌ی «بارگذاری فایل اسکن / عکس» همان‌جاست. دکمه‌های پایین: «ثبت جلسه و ارسال به لابراتوار» / «ثبت جلسه بدون ارسال به لابراتوار».
- ارسال (`m47Submit`): فقط بررسی‌های خودِ جلسه می‌ماند (نوع کار، نتیجه‌ی امتحان، دندان‌های جلسه برای کارهای دندانی، نوع چسب). سفارش با `order.m47 = 1` می‌رود.
- سرور برای سفارشِ `m47`: `l8OrdErr` (ایمپلنت/Type/material) و بررسی دندان/نقشه‌ی `f7cOrderErr` و `labNew` رد می‌شود؛ «ساخت برای» خالی یا نامعتبر = اولین مرحله‌ی مجاز مسیر بیمار؛ دندان خالی = دندان‌های جدول جلسه (یا نقشه‌ی بیمار)؛ تاریخ خالی/خراب = ۱۰ روز بعد. علامت `m47` در سفارش ذخیره نمی‌شود.
- می‌ماند: قواعد مسیر (`f7cForErr`: توقف درمان، موقتِ All-on-X، «اول قالب‌گیری») و پرسش تاریخ گذشته / قالب‌گیری روز جراحی. مسیرهای دیگر سفارش (پذیرش از پرونده = `labNew`، سفارش خود لابراتوار) مثل قبل سخت‌گیرند؛ `labNew` با action علامت را پاک می‌کند.
